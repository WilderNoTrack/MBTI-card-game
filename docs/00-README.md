## 🔧 容易踩的坑（提前避开）

### 1. Supabase Realtime 没启用
建好表后，记得在 SQL 里执行：
```sql
ALTER PUBLICATION supabase_realtime ADD TABLE game_rooms;
```

### 2. Row Level Security (RLS)
开发期建议**关闭 RLS**，否则各种权限报错调到崩溃。
等上线再开。

### 3. Claude API 返回非JSON
一定要做 fallback，详见 `04-AI-Prompts.md`。

### 4. 多人状态同步
所有状态变更都走服务端API，不要让客户端直接改 game_rooms 表。

### 5. 牌的效果不要全部实现
56张卡 + 多张AI生成卡，每张都做精细化的效果实现根本来不及。
建议：
- 基础卡（24张）必须实现
- 专属卡（32张）实现一半够用
- AI生成卡用一个简化的通用执行器即可

### 6. Demo 现场网络不稳定
**一定要提前录一份完整流程视频**，万一现场卡了能立刻切换播放。

## 📊 评审可能问的问题（提前准备答案）

1. **"这跟普通卡牌游戏有什么不同？"**
   → 卡牌是玩家自己生成的，不是预设的。每个人的牌组都是独一无二的。

2. **"为什么用MBTI不用别的人格框架？"**
   → MBTI对玩家来说理解成本低、有娱乐属性、社交属性强。我们的设计可以替换成大五人格或其他模型。

3. **"AI生成的牌会不会破坏平衡？"**
   → 我们用稀有度规则严格限制 cost/exposure，AI只能在预设效果池里选，不能超出范围。

4. **"商业模式？"**
   → 文旅快闪、阿那亚那种社交活动场地、线上Web3社交、心理工作坊。

5. **"为什么不直接做桌游？"**
   → 网游版便于MVP验证，跑通后可以转桌游。两种形态可共存。
