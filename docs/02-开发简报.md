# 人格对战卡牌游戏｜Claude Code 开发简报

> 直接把这份文档（连同其他三份）粘给 Claude Code，让它开始开发。

---

## 一、项目目标

**48小时黑客松项目**，做一个可演示的多人在线人格博弈卡牌游戏 MVP。

**核心演示目标**：评审能在5分钟内体验到完整的"选MBTI → 回答问题 → AI生成专属卡牌 → 多人对战"流程。

---

## 二、技术栈

| 类别 | 选择 | 原因 |
|------|------|------|
| 框架 | Next.js 14 (App Router) | 前后端一体，省时间 |
| 数据库 + 实时 | Supabase | Realtime 订阅简单，免费够用 |
| AI | Anthropic Claude API (`claude-sonnet-4-20250514`) | 卡牌和问题生成 |
| 样式 | Tailwind CSS + shadcn/ui | 快速搭UI |
| 部署 | Vercel | 一键部署 |
| 语言 | TypeScript | 类型安全，AI生成代码质量更高 |

**不要引入**：
- 状态管理库（Zustand/Redux）→ React state + Supabase 已经够用
- Socket.io → 用 Supabase Realtime 替代
- ORM（Prisma 等）→ 直接用 Supabase client

## 三、数据库结构（Supabase）

### 表：game_rooms

```sql
CREATE TABLE game_rooms (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  room_code TEXT UNIQUE NOT NULL,           -- 6位数字房间码
  status TEXT NOT NULL,                     -- waiting | setup | playing | finished
  current_round INTEGER DEFAULT 0,          -- 当前轮次（0-5）
  current_phase TEXT,                       -- question | resonance | battle
  current_turn_player_id TEXT,              -- 当前出牌玩家ID
  current_question JSONB,                   -- 当前问题对象
  players JSONB NOT NULL DEFAULT '[]',      -- 玩家列表（见下）
  game_log JSONB DEFAULT '[]',              -- 行动日志
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- 启用 Realtime
ALTER PUBLICATION supabase_realtime ADD TABLE game_rooms;
```

### players JSONB 结构

```typescript
type Player = {
  id: string              // 客户端生成 UUID
  nickname: string
  mbti: string            // INTJ | INTP | ... 共16种
  group: 'IN' | 'IS' | 'EN' | 'ES'
  hand: Card[]            // 手牌
  deck: Card[]            // 牌库（基础卡组初始）
  discard: Card[]         // 弃牌堆
  hidden_skill: Card | null  // 隐藏技能牌（第5轮生成）
  hp: number              // 0-10
  cost: number            // 代价槽 0-10
  exposure: number        // 公开度 0-10
  resonance_with: string[] // 与哪些玩家有共鸣链接
  is_alive: boolean
  setup_complete: boolean // 是否完成初始设置
  current_answer: string | null  // 本轮回答（用于AI生成卡）
  answer_visibility: 'public' | 'private' | 'skipped' | null
}

type Card = {
  id: string
  name: string
  description: string
  effect: string          // 效果文本
  effect_code: string     // 程序化效果ID（见游戏逻辑模块）
  cost: number            // 代价槽变化
  exposure: number        // 公开度变化
  rarity: 'base' | 'signature' | 'common' | 'rare' | 'hidden'
  type: 'info' | 'attack' | 'defense' | 'resonance' | 'utility' | 'special'
}
```

## 五、核心流程实现

### 5.1 创建房间

```typescript
// POST /api/room/create
// 生成6位随机数字房间码
// 在 game_rooms 插入新记录，status='waiting'
// 返回 room_code
```

### 5.2 加入房间

```typescript
// POST /api/room/join { roomCode, nickname }
// 检查房间存在且 status='waiting'
// 检查人数 < 6
// 将玩家信息 append 到 players 数组
// 客户端订阅 Supabase Realtime
```

### 5.3 房主开始游戏

- 检查人数 ≥ 4 且 ≤ 6
- 更新 status='setup'
- 客户端跳转到 setup 页面

### 5.4 MBTI 选择（setup 阶段）

每个玩家独立完成：
1. 选择16个MBTI类型之一
2. 系统从 `cards.ts` 分配该类型对应的8张基础卡组
3. 标记 `setup_complete = true`
4. 当所有玩家都 `setup_complete` 时，进入第1轮

### 5.5 主游戏循环（play 阶段）

每轮流程：

**Phase 1: question**
- 服务端从问题池随机抽取一个问题（按轮次决定深度）
- 写入 `current_question`，所有客户端通过 Realtime 收到
- 设置30秒倒计时
- 每个玩家提交回答 + 可见性选择

**Phase 2: resonance**
- 所有玩家可以看到他人的公开回答
- 点击「我也是」建立共鸣
- 持续15秒

**Phase 3: card_generation**
- 服务端调用 Claude API 为每个回答了的玩家生成卡牌
- 卡牌加入 `hand`
- 第5轮生成的是隐藏技能牌，存入 `hidden_skill`

**Phase 4: battle**
- 按 `players` 数组顺序轮流出牌
- 当前玩家 `current_turn_player_id`
- 每人每轮最多出2张牌
- 出牌后调用 `game/play-card` API，服务端验证 + 执行效果
- 一轮所有玩家都出完牌后，进入下一轮的 question phase

## 六、游戏逻辑模块设计

### `/lib/gameLogic.ts`

核心函数：

```typescript
// 执行卡牌效果
function executeCard(
  game: GameState,
  playerId: string,
  cardId: string,
  targetId?: string  // 可选目标玩家
): GameState

// 检查能否出牌
function canPlayCard(
  game: GameState,
  playerId: string,
  card: Card
): { ok: boolean; reason?: string }

// 检查胜利条件
function checkWinConditions(game: GameState): {
  gameEnded: boolean;
  winners: { playerId: string; condition: string }[]
}

// 进入下一阶段
function advancePhase(game: GameState): GameState
```

### `/lib/cardEffects.ts`

每张卡的 `effect_code` 对应一个函数：

```typescript
const cardEffects: Record<string, EffectHandler> = {
  'deal_damage_2': (state, player, target) => { ... },
  'view_hand_card': (state, player, target) => { ... },
  'heal_2': (state, player) => { ... },
  // ... 全部基础效果
}
```

为了赶进度，所有效果都先实现成纯函数，不要做复杂的动画或时序处理。

## 七、AI 集成

### 路由 `/api/ai/generate-card/route.ts`

接收：
```typescript
{
  mbti: string,
  question: string,       // 当前问题
  answer: string,         // 玩家回答
  depth: 'common' | 'rare' | 'hidden'
}
```

调用 Claude API（见 `04-AI-Prompts.md`），返回结构化卡牌JSON。

**关键**：服务端要做兜底——如果 Claude 返回的JSON解析失败或不符合格式，要返回一张预设的fallback卡牌，绝对不能让游戏卡住。

```typescript
const fallbackCards = {
  common: { name: '随手一击', effect: '造成2点伤害', ... },
  rare: { name: '深层共鸣', effect: '建立共鸣链接', ... },
  hidden: { name: '未命名之力', effect: '查看一名玩家的手牌', ... }
}
```

## 八、Realtime 订阅

客户端订阅：

```typescript
const channel = supabase
  .channel(`room:${roomCode}`)
  .on('postgres_changes', {
    event: 'UPDATE',
    schema: 'public',
    table: 'game_rooms',
    filter: `room_code=eq.${roomCode}`
  }, (payload) => {
    setGameState(payload.new)
  })
  .subscribe()
```

**注意**：所有状态变更都走服务端API，客户端只是显示。不要让客户端直接修改 game_rooms 表，否则会有并发问题。

## 九、开发优先级

### Day 1（前24小时）必须完成
1. ✅ Supabase 表结构 + RLS 设置
2. ✅ 创建/加入房间流程
3. ✅ MBTI 选择 + 基础卡组分配（用 `cards.ts`）
4. ✅ 问题阶段 + 回答提交
5. ✅ Claude API 接入 + 卡牌生成
6. ✅ 基础战斗循环（出牌、伤害、回合切换）
7. ✅ 胜利判定

### Day 2（24-40h）打磨
1. UI 优化（卡牌设计、动画）
2. 共鸣链接的视觉表现
3. 结局页 + 人格映射卡
4. Bug 修复

### Day 2（40-48h）准备 Demo
1. 准备3-5分钟演示流程
2. 录制 backup 视频以防现场出问题
3. 准备 pitch deck

### 不要做（来不及）
- 用户系统/登录
- 房间历史记录
- 详细的卡牌动画
- 移动端适配（演示用桌面）
- 国际化
